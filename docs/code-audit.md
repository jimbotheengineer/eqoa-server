# EQOA server code audit

The review started at upstream commit `0d2a0ed531200cef074fd36b94b8653377af21b8` on November 22, 2026. The highest-priority findings concerned operator data in release archives, recovery from SQLite backups, and account authorization across password changes. The fixes are on this fork's `main` branch.

## Scope and evidence

The baseline contained 3,268 tracked files, including 2,281 Go files, 765 Python files, 138 JSON files, 48 JavaScript files, eight SQL recipes, and three shell scripts. The Go module contained 60 packages and 31 command directories. The sibling ESF dependency used for verification was `87b79805071076ba45d55834110be9533a2d4f9b`.

Whole-tree checks covered Go static analysis and tests, Python parsing and test discovery, JavaScript and shell syntax, JSON parsing, and secret detection. Manual review followed authentication, account and GM pages, relay and game protocols, session state, database access, import/export, release, and recovery paths. Gameplay and asset review sampled individual implementations and their tests. Manual coverage was risk-based.

## Findings and changes

| Priority | Source finding | Fix and evidence |
|---|---|---|
| High | Release packaging copied an operator database into a distributable archive. Its cleanup covered only selected tables and could fail before packaging. | The packager excludes runtime databases, selects tracked source, builds in private staging, and verifies a new archive before publishing it. A synthetic archive test checks contents and preservation of a previous release after failure. See [packager](../tools/make-distro.sh) and [test](../tools/make_distro_test.py). |
| High | Thirty-nine maintenance scripts copied only the SQLite main file. Committed character, account, or content changes can still be in the WAL. Cold rollback could also discard saves made during shutdown. | The shared backup helper uses SQLite's backup API, publishes completed private files, and preserves same-name backups. Swap scripts restore through SQLite and take cold backups after shutdown saves. See [backup tests](../tools/sqlite_backup_test.py) and [swap tests](../tools/swap_when_empty_test.py). |
| High | A password change or suspension could leave account access available through an already-issued credential. The account e-mail authenticator check also depended on GM listener startup. Concurrent legacy hash upgrades could overwrite a reset. | Game tickets, account-page sessions, and transfer sessions recheck the account. Legacy upgrades compare-and-swap the observed hash. Account e-mail checks stored authenticator enrollment before serving requests, including when the panel is offline. See [ticket tests](../internal/handlers/authtoken_test.go), [web session tests](../internal/network/tcp/accountpassword_test.go), [transfer tests](../internal/transfers/transfers_test.go), and [authenticator tests](../internal/gmweb/account_totp_test.go). |
| High | The SQL importer removed its destination before opening the dump. Character imports could clear an inventory and commit a partial replacement after a parse or write error. | SQL import now requires a new destination and publishes a completed private database. Capture imports validate the record sections they consume and apply all row changes in one transaction. JSON item and spell imports also share a transaction. See [SQL import tests](../cmd/sqlimport/main_test.go) and [capture tests](../cmd/importdump/main_test.go). |
| High | Stored character display data was interpolated into account-page HTML. Remote SMTP could deliver account recovery mail without verified encryption. | Account pages insert dynamic display values as text. Remote SMTP requires authenticated STARTTLS with TLS 1.2 or newer. Mail retries have a shared capacity limit. See [account pages](../internal/network/tcp/accountserver.go) and [mailer tests](../internal/mailer/mailer_test.go). |
| Medium | Some GM authorization and token state changes spanned separate writes. A failed refresh could revoke the old credential without delivering a replacement. SQL inspection, JSON framing, and administrative backups had weaker boundaries than their interfaces promised. | Token issuance and refresh rotation are transactional. Browser revocation is synchronized, JSON endpoints validate media type and framing, read-only PRAGMAs restrict arguments, and backup/config files use private, unique names. See [OAuth code](../internal/gmweb/oauth.go), [security tests](../internal/gmweb/security_test.go), and [config backup tests](../internal/config/edit_test.go). |
| Medium | Station login assumed a TCP read contained exactly one frame. The relay used only the local port for client attribution. UDP dispatch and per-address bookkeeping could grow without an effective bound. | Login reads complete frames. Relay lookups distinguish TCP and UDP, with ambiguous legacy lookups refused, and the lookup listener enforces loopback binding. UDP processing caps in-flight work and releases address ordering records. See [TCP tests](../internal/network/tcp/login_test.go), [relay tests](../internal/wsrelay/relay_test.go), and [UDP tests](../internal/network/udp/fragments_test.go). |
| Medium | Shard account refresh checked the main database file for changes and could delay propagation of a change committed to the WAL. Several diagnostic commands also ran server startup migrations on the database being inspected. | The mirror observes WAL changes. Read-only tools open the source read-only, and simulations and migration backups take consistent snapshots. See [mirror tests](../internal/database/accountmirror_test.go) and [offline database tests](../internal/database/offline_test.go). |
| Medium | Fresh installs using the example config created a known account and exposed account HTTP on all interfaces. Ordinary new SQLite files inherited system defaults that could allow other local users to read account data. | The sample has no active credentials and binds the account page to loopback. New server database files use private permissions. Existing database modes are retained. See [configuration](../config.yaml.example) and [file mode regression](../internal/database/filemode_test.go). |

The Go dependency scan initially reported 18 advisories at module level on Linux, with zero called vulnerable symbols. Updating `x/crypto`, `x/sys`, and the recommended Go toolchain cleared the reports on Linux and Windows. The source originally bundled SQLite 3.51.2 and enables WAL on startup. The upgraded driver bundles SQLite 3.51.3, which fixes a rare corruption race involving concurrent writes and checkpoints. Python tools and the SQLite CLI use the SQLite provided by their environment. [SQLite advisory](https://sqlite.org/wal.html#walresetbug) · [Go release history](https://go.dev/doc/devel/release)

Other corrections include counting UTF-16 code units on the game wire, preserving the health and power regeneration stat IDs during imports, retaining NPC rows when a SQL recipe's template is absent, and protecting 39 additional case-sensitive NPC names during name normalization.

## Efficiency measurements

| Operation | Original | Revised | Conditions |
|---|---:|---:|---|
| Wire CRC of 1 KiB | 1,482–1,499 ns | 26–32 ns | Three 400 ms runs on the same machine with the same benchmark loop. The standard library's IEEE CRC is adjusted to preserve the wire checksum, with a fixed-vector regression. |
| Password-reset limit lookup | 13.0 ms | 0.024 ms | Median of eight runs on a synthetic 100,000-row reset history. SQLite's query plan changed from a full scan to four indexed searches. |

These figures apply to the two operations measured. End-to-end game latency, tick rate under load, and production throughput were outside the measurements.

## Operator impact

- Build the fork with the toolchain in `go.mod` and the sibling dependency revision in the README. Roll out the WebSocket relay before the game server if they are updated separately. Older clients can still use unambiguous port-only lookups.
- Configure a trusted TLS certificate on a remote SMTP relay, or send through loopback. A fresh account configuration requires the operator to supply any precreated credentials. Review access to existing database files and backups separately from the new-file defaults.
- Use a fresh output path with `cmd/sqlimport`. Content distributions now obtain the public game database separately. The changed packaging process cannot establish what a previously published archive contained.
- Keep `auth.require_tcp_login` enabled on public servers. Retail Station authentication uses fixed protocol keys, so native client traffic remains a legacy transport risk. An HTTPS reverse proxy protects the web endpoints. Access control for native TCP/UDP is a separate deployment decision.

## Verification and remaining limits

- Tests used disposable databases, synthetic network peers, and local fixtures. The full Go suite passed across 60 packages. It recorded 4,982 passing test and subtest events and 219 skips. Twenty packages have no Go tests. Statement coverage was **72.4%**. `go vet ./...`, module checksum verification, Linux builds, Windows amd64 cross-builds, and `govulncheck ./...` for both targets passed.
- The race detector ran across all 60 packages. Four large packages were split into 47 groups covering their 4,217 top-level tests. Eight handler fixtures failed the first pass. Seven accessed mutable test state while workers were running, and one used a timestamp captured before database setup. After correction, all eight passed together under the race detector. The other groups and packages passed. Separate race checks covered credential changes, transfer-cookie revocation, database creation, relay attribution, and rollback. The mercenary recovery fixture passed 500 repetitions after its owner was held stationary. A concurrent formula test now bounds its synthetic traffic below the logger's drop threshold and passed eight race-detector repetitions.
- Python discovery ran 1,269 tests. **1,238 passed, 26 skipped, and five failed.** The five also fail on the untouched upstream baseline. They compare historical tuning migrations with a later common balance seed in `internal/database/balanceseed.go`. The affected suites are `tune_balance`, `retune_balance`, `refit_eqoaemu_balance`, `refit_eqoaemu_followup`, and `refit_eqoaemu_followup2`. Reconciling the assertions requires choosing the intended historical balance baseline.
- Staticcheck reported 23 diagnostics with the `SA*` checks. Seventeen concern tests. The six in runtime code concern constant declarations, a lock barrier, an overwritten cleanup function, and a redundant bit operation.
- Gitleaks flagged 75 generic-key candidates in the working tree. Review identified quest identifiers/content keys and one synthetic shard key in a test. Bandit's nine high-severity flags concerned MD5/SHA-1 use for deterministic game data or legacy row fingerprints. These fingerprints support repeatable game-data generation and undo checks.
- The seven multi-statement NPC seed recipes still rely on the caller to roll back SQL errors. Run them in a transaction with error handling. Legacy imports support the documented dump formats. The capture importer rejects auction, corpse, or spell sub-records it cannot decode.
- The release packaging regression uses synthetic assets and a stub compiler. The real Go commands were built separately. Production databases, a full disc image, real console clients, hosted TLS/SMTP, and existing release archives were outside the audit. The review also excludes historical Git objects and third-party code beyond dependency checks and interface tracing.
